# 热点问答安全设计

热点问答采用受控的四阶段流程：

1. 后端先在规范主题与别名词表中匹配用户原问题，最长、最具体的主题优先。
2. 模型结合已匹配主题和六类示例，只能输出受约束的 JSON 查询计划；意图限制为排行、趋势、对比、关联、公开研究列表和领域摘要。
3. 后端以 Pydantic 校验并修复计划。主题类查询缺少主题时使用词表结果补全；仍无法识别则明确返回错误，禁止降级成无关热榜。
4. 后端执行固定、参数化的仓储方法，再把有限的结构化结果交给模型组织回答。

模型不会获得数据库连接，不能提交或执行 SQL，也无法查询私有研究、用户密钥或现有研究数据库。模型不可用或输出无效时，系统使用确定性规则生成查询计划和答案，研究广场仍可使用。

规划提示词内置六类多样化示例：热门排行、主题关联、单题趋势、主题对比、公开研究和领域概览。前端问答窗口展示相同示例，点击即可填入并继续修改。

趋势查询由后端计算，不让模型自行推断。90 天查询分成三个连续 30 天周期，每段返回热度、新增研究数和相对上一周期的环比；模型必须逐段说明并给出上升、下降或稳定结论。

## OpenAlex 批量增强

- 主题级：AI 根据 OpenAlex 主题、子学科、学科和领域生成中文规范名、中文别名，并补充项目内部的多领域归属。
- 论文级：只复核主主题分数低于 0.5 的论文，并且只能在 OpenAlex 已给出的前三个候选主题中选择。
- 原始字段不可覆盖：AI 结果写入独立 enrichment/review 表，低置信度 AI 结果标记为待人工审核。
- 批次可恢复：已经完成的主题和论文不会重复调用；任务记录模型、提示词版本与 token 用量。
