# 任务 1: 架构范式演进

【任务概览】探究2025年多模态大模型在架构层面的范式转向。
【核心意图】厘清从「视觉编码器+LLM 拼接式」向「原生统一多模态（any-to-any / early-fusion / tokenizer-free）」的演进路径与路线分歧。
【检索方向】native multimodal LLM architecture 2025; any-to-any unified transformer; early fusion vs late fusion; tokenizer-free / discrete visual token; omni-modal 统一建模；视觉 token 压缩与长上下文。
【预期产出】架构演进时间线与技术路线对比表（代表模型、融合方式、模态覆盖、上下文长度）。
【边界】不涉及具体榜单分数与商业落地，交由任务3、任务5。

【本轮新增：架构分层的正式化】
- 四层范式谱系：(1) 晚融合 late fusion = 冻结/预训练视觉编码器 + connector（投影层）+ LLM，代表 LLaVA、Qwen3-VL、Idefics3；(2) 交叉注意力注入 = Perceiver Resampler 将变长视觉特征压成固定数量 latent token，由冻结 LM 中的 gated cross-attention 读取，代表 Flamingo；(3) 中融合 mid-fusion = 多编码器特征注入统一多模态骨干，保留显式模态边界（CogVLM 2023.11、Qwen-Audio 2023.11、Qwen2.5-VL 2025.02 一脉）；(4) 早融合 early fusion = Transformer(∪_i T(m_i))，全模态由统一算子映射进共享嵌入空间，从预训练第一步即同骨干混训。
- Roadmap 论文以 input-output 对偶性做三分类：Multi-to-Text（跨模态理解，仅文本输出）、Multi-to-Target（场景化生成，如文生图/音/视频）、Multi-to-Multi（输入输出对称的统一建模）。
- 「原生度」不是二元标签，而是连续谱：Llama 4 同时被描述为 native early fusion 且使用 MetaCLIP-based encoder；Qwen3-VL 仍为 ViT→LLM + Interleaved-MRoPE，但主打 256K 原生交错上下文。

【本轮新增：缩放与实证证据】
- Apple + Sorbonne 在 ICCV 2025 训练 457 个原生多模态模型，未发现晚融合相对早融合的固有优势（反驳「拼装式更安全」的默认假设）。
- 缩放律：N∝C^0.53(dense)、N∝C^0.36(MoE)、D∝C^0.66(MoE)，等算力下早融合不劣于晚融合，MoE 收益显著。
- Meta Llama 4（2025-04，Scout 109B-A17B / Maverick 400B-A17B）以 >30T 文本+视觉 token 训练；Chameleon（2024-05，34B）已证离散 token 早融合可扩至 34B；GPT-4o（2024）亦属原生早融合设计。

【本轮新增：工程取舍与失败模式】
- Chameleon 在 8B / 1T token 规模出现晚期训练发散，根因是同一骨干内各模态信号相互竞争（图像生成需极端激活值，破坏其余模态），解法为关键位置信号归一化（QK-Norm 类）。
- 视觉 token 成本：Claude 4.7 及以后单张高分辨率图最高 4,784 visual token（1 token / 28×28 patch）；缓解手段包括 tokenizer-free（Fuyu-8B 直接喂原始 patch，无视觉编码器）、视觉 token 压缩、patchification 与 RoPE 频率基扩展以支撑 64K 乃至更长上下文。
- MoE 稀疏激活（如 Aria 66 专家仅激活约 8）在近乎不增算力下保留模态专属容量。

【本轮新增：能力边界迁移（理解-only → 理解+生成）】
- Multi-to-Multi 阵营 2024→2025 快速扩张：AnyGPT(7B,2024.02)、Chameleon(34B,2024.05)、Transfusion(7B,2024.08)、Moshi(7B,2024.09)、Janus-Pro(7B,2025.01)、BAGEL(14B-A7B,2025.05)、Show-o2(7B,NeurIPS 2025)、OneCat(9B-A3B,2025)、Emu3.5(34.1B,2025.10)、Lance(2026.05,3B)。
- 统一目标函数：自回归 next-token（跨全模态词表并集）+ flow matching / 掩码图像 token 扩散的联合损失；Show-o 用「AR 文本 + 掩码图像 token 扩散」，Show-o2 用「AR 文本 + 视觉 flow matching」，OneCat 引入模态专属专家。
- Omni/实时维度：GPT-4o 语音最低 232ms、平均 320ms；Gemini 2.5 单上下文可处理至多 3 小时视频（2025-07）。

【结论（本轮）】2025 年架构主线是「晚融合作为工程默认」被「早融合/原生统一」在缩放律与实证上正面挑战，但由于训练稳定性、数据配比与视觉 token 成本约束，工业落地普遍呈现「统一骨干 + 模态专属组件」的混合形态，真正全组件从零训练的原生模型仍属少数。
