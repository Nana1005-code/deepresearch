任务 1 目标意图：基于 Python 官方文档确认 asyncio 的核心用途——单线程内通过事件循环与协程调度处理大量并发 I/O（网络、数据库、子进程、队列等），即以 async/await 语法构建的异步 I/O 并发框架；同时记录其适用边界（CPU 密集型任务不适用，应交给多进程/线程池）。

官方核心定义原句：This module provides infrastructure for writing single-threaded concurrent code using coroutines, multiplexing I/O access over sockets and other resources, running network clients and servers, and other related primitives.
官方包内容清单（8 项）：① 可插拔事件循环（各系统特定实现）；② transport 与 protocol 抽象（类似 Twisted）；③ TCP、UDP、SSL、子进程管道、延迟调用的具体支持（部分依赖系统）；④ Future 类（仿 concurrent.futures，适配事件循环）；⑤ 基于 yield from（PEP 380）的协程与 Task，可“以顺序方式书写并发代码”；⑥ Future 与协程的取消支持；⑦ 单线程协程间同步原语（仿 threading）；⑧ 将工作交给线程池的接口，用于必须调用阻塞 I/O 库的场合。
限制与成本提示（官方原文）：异步编程比传统“顺序”编程更复杂，参见 Develop with asyncio 页面列出的常见陷阱；建议开发期开启 debug 模式（asyncio-debug-mode）检测常见问题。文档目录结构印证用途分层：Base Event Loop（run/calls/delayed calls/tasks/创建连接/监听连接/watch 文件描述符/低层 socket/解析主机名/连接管道/UNIX 信号/executor/Server）→ Event loops（平台支持 Windows/macOS、事件循环策略）→ Tasks and coroutines（Coroutine/Future/Task/并行执行任务）→ Transports and protocols（含 TCP/UDP echo client/server 示例）→ Streams（基于协程的高层 API）。

来源概览补充说明：本轮全部证据来自 docs.python.org 官方页面，未使用二手博客；3.4/3.5/3.6 三版正文表述高度一致，说明 asyncio 用途定位自 3.4 引入以来保持稳定；早期“provisional basis”标注提示允许不兼容变更（乃至移除），反映其标准库地位的演进过程。

任务总结（限 300 字以内）：
官方定义：asyncio 是编写单线程并发代码的基础设施，基于协程，在 socket 等资源上多路复用 I/O，并可运行网络客户端与服务器。
核心用途：①可插拔事件循环驱动调度；②协程/Task（基于 yield from，PEP 380）让并发代码顺序化书写；③transport/protocol 抽象与 TCP/UDP/SSL/子进程管道、延迟调用等具体支持；④Future、取消、单线程同步原语等编排原语。
典型场景：高并发 I/O——网络客户端/服务器、数据库与子进程管道、socket 多路复用。
边界：CPU 密集型不适用（应交给多进程/线程池）；阻塞 I/O 库需经线程池接口转交；官方明确异步编程比顺序编程更复杂，需防常见陷阱并开启 debug 模式。
