# 任务 3: 视频时序理解

## 任务概览
任务目标：回答多模态模型能否理解长视频与实时流，聚焦长上下文扩展、时序定位与视觉 token 压缩等关键技术瓶颈。

- 已完成：streaming video LLM real-time

- 覆盖来源：EmergentMind Video LLM 主题页；Awesome-Streaming-Video-Understanding（含 2026.06 综述）；Watch-Remember-Reason 综述（arXiv 2606.07433）；STORM 论文（NVIDIA, arXiv 2503.04130）；相关视频/解读。

## 关键发现
1. 结论：长视频理解在 2025 年已基本从“不可能”转为“可工程化”——核心答案是「先注入时序、再压缩 token」。STORM（NVIDIA）在 SigLIP 编码器与 LLM 之间插入双向 Mamba 时序投影器，先让每个视觉 token 携带全片上下文，再做时间平均池化（4:1）与训练无关的隔帧采样（2:1），合计 8× token 压缩，视觉算力降至约 1/8、推理约快 3 倍，在长视频基准上超过 GPT-4o。关键反直觉点：缺少 Mamba 模块时，单纯拉长视频+压缩，基线 VILA 收益递减——说明压缩必须建立在时序已编码的前提上。
2. 结论：实时流是比长视频更硬的瓶颈，因为引入了“因果约束 + 主动性”两重新问题。流式模型无法回看或预览未来帧，任何时刻只能依赖过去与当前信息；同时必须解决『何时该说』（proactive）——用 EOS token 触发、专用分类器、困惑度校验、视觉检测等机制。Awesome-Streaming-Video-Understanding 将其归纳为两大根本挑战：Proactive Decision-Making（When to Act）与 Efficient Resource Management（How to Sustain）。
3. 结论：视觉 token 压缩已形成“分层 + 缓存 + 检索”三件套的成熟工程范式。CVPR 2026 的 STC 用 STC-Cacher 复用时间相近帧的 ViT 特征、STC-Pruner 在 LLM prefill 前按时空相关性/新颖度剪枝；CacheFlow 做压缩式流式记忆；StreamKV（AAAI 2026）用分段 KV cache 检索与压缩；更早有 R-VLM、VidCompress、VideoStreaming 的软匹配/检索/记忆选择损失。这标志压缩从“均匀丢帧”走向“按相关性选择”。
4. 结论：时序定位（VTG）正从专用检测头转向“生成式 grounding”——时间戳被当作统一多模态词表中的语言 token，由 LLM 直接生成 start/end 或高亮区间。数据侧出现标准化时间 token 的 VTG-IT-120K、多步验证高精度 TimeLens-100K、支持片段裁剪工具调用的 MTVR（72K SFT + 110K RL）；历史脉络为 TimeIT(2023,125K)→VTimeLLM(2024,134K)→VTG-IT-120K(2025)。
5. 结论：“watch–remember–reason”（看—记—推理）是人类视角的统一分析框架，揭示长视频的根本矛盾是「冗余 vs 证据稀疏」：长视频大量冗余帧，但决定性证据可能只出现一瞬。因此系统需三者协同：选择性感知（对应高效感知与时空 grounding）、紧凑记忆（对应有限预算下的长程上下文）、忠实推理（答案需可回溯到显式时空证据）。相关数据集：VideoMarathon（3.3M 小时级指令数据）、M3-Agent（实体中心长期记忆）。

## 结论
- 能否理解长视频：2025 年已可做到，靠「时序优先编码 + 分层 token 压缩 + 记忆/检索」；STORM 是标志性方案（8× 压缩、超 GPT-4o）。
- 能否理解实时流：部分可行但仍是前沿——主要卡点是因果约束下的主动决策（何时开口）与恒定预算下的 KV cache/记忆管理，代表工作 STC、StreamKV、CacheFlow、LiveStar、MMDuet2。
- 三大技术瓶颈均已出现明确解法方向：长上下文扩展→分层压缩+流式记忆+问题引导检索；时序定位→时间戳 token 化+生成式 grounding；视觉 token 压缩→时序先编码再压缩。
