# 任务 4: 多模态智能体

## 任务概览
- 任务目标：判断多模态能力是否从「看懂」走向「操作」，评估 GUI Agent、Computer Use 与具身智能的真实可用度及典型失败模式。
- 核心问题：OSWorld 等基准上的成功率能否反映真实可用度？

## 已收集信息
- OSWorld：369 任务（Ubuntu）+43（Windows），134 个执行型评估函数；人类 72.36% vs 最佳模型 12.24%（GPT-4/Mixtral/CogAgent 等基线）。
- 环境机制：pyautogui 驱动的鼠标键盘事件、可从中途状态初始化、多模态观测（截图 + a11y 树 + 终端输出）；Ubuntu 为主，扩展 Windows/macOS；含 ≈8% 不可行任务用于测试「拒绝/识别不可完成」能力。
- 失败模式：GUI grounding（点击坐标错、重复误点、杂乱动态界面映射失败）、operational knowledge（应用语义不熟、菜单/设置误操作、试错循环）、长程规划（步数一长成功率骤降、记忆/上下文跟踪/子目标分解弱）。额外暴露环境噪声恢复失败（意外弹窗、状态异常）。
- 扩展：OSWorld-G（564 样本 grounding 套件 + Jedi 数据集）、OSWorld-Human（人类轨迹，顶级 agent 步数 1.4–2.7×）；OSWorld-Verified（2025-07-28，修复社区报告样例 + AWS 支持，评估 <1 小时）；OSWorld 2.0（2026-06-26）。
- 时间线：OSWorld 12%（2024-04）→85%（2026-06）；OSWorld 2.0 上最佳仅 20.6%（人类中位 1.6 小时）。
- 效率问题：延迟主要来自规划与反思的大模型调用，步数越靠后单步耗时可≥起始步 3 倍；端到端常达数十分钟（人类数分钟）。
- 方法学影响：经验增强层次规划、多智能体协作、GUI+代码混合控制均以 OSWorld 为评估场；推动「截图+a11y 融合感知 + 显式 grounding 模块 + 记忆/反思机制」架构转向；与 MCP 等 agent-native 接口形成「像素驱动 vs 原生接口」路线之争。
