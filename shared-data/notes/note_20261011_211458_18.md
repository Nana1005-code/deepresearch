# 任务 4: 系统与落地

# 任务 4: 系统与落地

## 任务概览
任务目标: 梳理 DocVQA 从单模型走向工程系统的实践路径，包括视觉 RAG、多步 Agent 文档工作流、页面级检索与精读的分工，以及精度-延迟-成本的实际权衡。

## 关键发现

### 发现 1：2026 年 DocVQA 的工程范式已从「单模型问答」转向「Agentic + 多模态 + 多索引」的检索系统
- 2024 年的 RAG 是「embed query → top-k → stuff prompt → generate」的线性管道；2026 年的系统是「classify query → route to tools（向量索引/知识图谱/SQL/代码搜索）→ 分阶段 retrieve → rerank → 可选 reflect → generate」，编排层（orchestration layer）成为主要工程量所在。
- 两个可观测的趋势动作：(a) 检索从纯向量变为「文本 + 结构化数据 + 文档图像」的多模态多索引混合检索；(b) 单趟变为多趟——top-100 rerank + 可选反思步骤，是把答案正确率从 ~60% 拉到 ~85% 的关键。
- 数据支撑：Microsoft GraphRAG 研究显示，同一 LLM 用知识图谱 grounding 后，多跳推理准确率从 16.7% 提升到 56.2%（3.4x）；cross-encoder rerank 再带来 33%–40% 的检索准确率提升，代价约 120ms p50 延迟。
- 价值：说明 DocVQA 不再是「选一个更强的 VLM」的模型问题，而是「架构选型 + 路由策略 + 分阶段检索」的系统问题。

### 发现 2：视觉 RAG 有三（四）条主流架构路线，对应不同的精度-成本曲线
- **Caption-and-index**：用 VLM 为每张图表/图像生成自然语言描述，与周围文本一起索引。最便宜，小语料上「往往够用」，但信息有损，caption 幻觉会污染索引。
- **Unified vision embeddings**：Cohere Embed 4、voyage-multimodal-3.5 把图文嵌入同一向量空间，单一索引、单趟检索、单向量存储；Embed 4 支持 128K 上下文（约 200 页 PDF 一次嵌入）、Matryoshka 维度 256/512/1024/1536 可按需压缩存储。代价是 API 依赖与单向量在困难图页查询上不敌多向量 late interaction。
- **Page-as-image with late interaction**：ColPali/ColQwen2 把渲染后的整页作为检索单元，多向量检索，在图密集文档上召回最高、无需解析管道；代价是每页向量数 100–1000x，多数引擎需自定义打分。
- **Hybrid late-fusion**：文本索引 + 图像索引并行，BM25 + dense + RRF 融合 + VLM reranker；最灵活、混合语料召回最好，但运营与评估最复杂。
- 大多数生产团队最终落在 #2 或 #4；#1 适合小语料快速见效；#3 适用于「答案真的在像素里」且召回是瓶颈时。

### 发现 3：页面级检索与精读存在明确分工，延迟预算是可以提前算清的
- 查询路径的标准分解：query embedding（托管 20–50ms / 本地 10ms）→ retrieval（30–80ms）→ 对 top-20 做 reranking（200–500ms）→ VLM 生成首 token 流式（1–2s）。端到端首 token <2s 可达，但**前提是页面图像在 ingest 阶段就渲染并预计算**（含缩略图），而不是查询时渲染。
- 精度-延迟分层：Naive RAG 70–80% 精度/最快；Modular RAG 85–95%/中等；GraphRAG 90–97%/+1–2s；Agentic RAG 92–99%/+3–6s。
- 成本要点：图像 token 化非平凡——1024x1024 单图块 Claude ~1600 tokens、Gemini ~1300、GPT-4o（high detail）~765；传 5 页图会额外增加 4K–8K+ 输入 token。这直接决定了「整页喂 VLM 精读」只能用于 rerank 后的少数页，而非全语料。

### 发现 4：2026 企业 RAG 的落地形态分层明确，选错层是最大的采购风险
- 市场：2025 年 ~$1.94B → 2030 年 $9.86B，CAGR 38.4%（MarketsandMarkets, 2025-11）。
- 三层结构：Turnkey 平台（Onyx、Glean、Cohere North、Vectara、GoSearch、Writer、SphereIQ）/ 云托管服务（AWS Bedrock KB、Azure AI Search、Google Gemini Enterprise、IBM watsonx）/ 自建基础设施与框架（Pinecone、Weaviate、Qdrant、Milvus、LlamaIndex、LangChain、Haystack、Elastic、RAGFlow）。
- 关键判据：MIT 2025 GenAI Divide 报告显示 95% 企业 GenAI 试点无法产生可衡量的 P&L 影响，且 vendor-partner 部署成功率约 67% vs 自建 33%。最常见错误是「需要平台时买了向量库，需要框架时买了平台」。
- 落地数据点：Onyx 在 Ramp 达 115K 查询/月、30–50x ROI；Thales 1,400 MAU / 82,000 员工；UC San Diego 37K+ 用户全气隙部署本地 LLM。

### 发现 5：评估与权限是「生产 vs Demo」的真正分水岭，也是成本结构的一部分
- 无评估即无生产：若不能度量 faithfulness、answer relevance、context precision，就不算生产 RAG；RAGAS 与 TruLens 是实践默认，DeepEval 亦被列为选项。2026 年团队拒绝对 faithfulness/context precision 有回退的版本上线。
- 权限必须在索引层于查询时强制（early binding，预检索过滤），而非对检索出的 chunk 做事后过滤（late binding），否则必然泄漏。
- 治理与合规：EU AI Act 2026-08-02 生效是选型的硬时间线；合规优先的对比把平台按检索质量、部署灵活性、主权、EU AI Act readiness 打分。
- 成本形态：开源框架 $0 起，大型企业年合同 $500,000+，中型托管平台约 $50–$100/用户/月，云原生按查询/嵌入文档/LLM token 计费（导致总成本在生产量未知前难预测）。LlamaCloud 计价：1,000 credits = $1，LlamaParse v2 从 3 credits/页（Cost-Effective）到 45 credits/页（Agentic Plus）。
